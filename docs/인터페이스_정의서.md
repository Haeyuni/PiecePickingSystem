# 인터페이스 정의서: sort_msgs

BR 문서·시스템명세서에 정의된 5계층(인지·파지·계획·실행·웹)이 실제로 주고받는 ROS2 메시지·액션·설정 파일의 스키마를 확정한다. 이 문서가 확정되면 각 계층은 서로의 내부 구현을 몰라도 이 인터페이스만으로 개발을 진행할 수 있다.

| 항목 | 내용 |
| --- | --- |
| 문서 버전 | v2.0 |
| 대상 패키지 | `sort_msgs` (ament_cmake), `perception`/`grasp`/`control`이 참조하는 `objects.yaml`/`bins.yaml` |
| 관련 문서 | BR 문서, 시스템명세서 |

---

## 1. 공통 필드 규칙

`perception`, `grasp`, `control`, `planner`, `web`은 각각 독립 컨테이너로 배포된다. 한쪽만 재빌드되고 다른 쪽이 안 바뀐 상태로 통신하면, 필드가 어긋난 채 조용히 잘못된 값을 주고받을 수 있다. 아래 네 필드는 이 문제를 막기 위한 것이며, **모든 메시지에 일괄 적용하지 않고 아래 기준에 따라 선택적으로 붙인다.**

| 필드 | 규칙 | 적용 대상 |
| --- | --- | --- |
| `schema_version` | 하위 호환 변경은 minor, 비호환 변경은 major 증가 (예: `"1.0.0"`) | **독립적으로 주고받는 최상위 메시지**(`WorldState`, `InstanceMasks`, `Pick`/`PlaceInto` goal, `RobotState`, `SafetyEvent`)와 **JSON API 경계**(web↔planner, web↔브라우저)에만. 다른 메시지 안에 중첩되어서만 쓰이는 `DetectedObject`, `GraspCandidate`는 부모 메시지의 버전을 따르므로 제외 |
| `trace_id` | 명령 입력(또는 음성 녹음 시작) 시점부터 결과 반환까지 동일하게 유지 | `web`이 명령 접수 시 발급. `WorldState`, `Pick`/`PlaceInto` goal, DB 각 테이블로 전파 |
| `sequence_id` | `trace_id`의 하위 개념 — 하나의 trace 안에서 `planner`가 시퀀스를 생성하는 시점에 발급 | `task_sequences`, `execution_logs` (기존 그대로 유지) |
| `request_id` | 개별 액션 요청 식별자. 재전송 시 같은 ID를 사용해 중복 실행 방지 | `Pick`/`PlaceInto` goal. `control`이 최근 처리한 `request_id`를 짧게 캐시해 중복 실행을 실제로 막아야 한다 — 필드만으로는 방지되지 않는다 |
| `created_at` / `stamp` | JSON·DB 경계는 ISO 8601 문자열로 `created_at`, ROS2 메시지 내부는 `builtin_interfaces/Time stamp`(ROS2 관례) | 이름 충돌 방지를 위해 경계를 넘을 때만 이름을 바꾼다 |

**추적 계층 구조**: 하나의 `trace_id` 아래 하나의 `sequence_id`, 그 아래 `Pick`/`PlaceInto` 호출마다 여러 개의 `request_id`가 달린다.

```
trace_id (명령 1건)
  └─ sequence_id (그 명령에서 생성된 시퀀스 1개)
       ├─ request_id (pick 호출 1)
       ├─ request_id (place_into 호출 1)
       └─ request_id (pick 호출 2, 재시도 시에도 동일 유지)
```

### 1.1 단위 규칙 (확정)

**모든 길이는 mm로 통일한다.** 계층 경계를 넘는 값(ROS2 메시지·액션, HTTP JSON, DB, `bins.yaml`)은 예외 없이 mm다.

| 종류 | 단위 | 예 |
| --- | --- | --- |
| 길이/좌표 | **mm** | `position_base_mm`, `gripper_width_mm`, `bins.yaml`의 `pose.x` |
| 회전 | 쿼터니언(무차원). 오일러로 표기할 때만 도(deg) | `geometry_msgs/Pose.orientation` |
| 시간 | ms | `cycle_time_ms` |
| 힘 | N | `max_grip_force_n`, `contact_threshold_n` |

근거: 두산 로봇 API(`get_current_posx`)와 hand-eye 결과(`T_gripper2camera.npy`)가 모두 mm 기준이다. 계층마다 단위를 바꾸면 1000배 오차가 조용히 섞여 들어온다.

**필드 이름에 단위 접미사를 붙인다**(`_mm`/`_ms`/`_n`). 단위를 이름으로 강제하면 문서를 안 봐도 틀리기 어렵다.

**단 하나의 예외 — ROS 표준 인터페이스**: ROS의 `geometry_msgs`는 REP-103에 따라 m가 관례이고, MoveIt2·tf2·`JointState` 등 외부 표준 스택은 m로 동작한다. 따라서 `sort_msgs` 안의 `geometry_msgs/Point`·`Pose`는 **우리 규칙(mm)을 따르되**, MoveIt2/tf2에 넘기거나 받는 순간에만 m로 환산한다. 이 환산은 `control` 내부 한 곳(`control/control/units.py`)에서만 수행하며, 다른 어떤 계층도 단위를 바꾸지 않는다 — 변환 지점이 둘 이상이 되는 순간 이 규칙은 무의미해진다.

## 2. 토픽·액션 개요

| 이름 | 종류 | 타입 | 발행/제공 | 구독/호출 |
| --- | --- | --- | --- | --- |
| `/perception/world_state_raw` | 토픽 | `WorldState` | perception | **grasp만** (내부 릴레이 입력) |
| `/perception/instance_masks` | 토픽 | `InstanceMasks` | perception | grasp (내부용, 2절 하단 참고) |
| `/world_state` | 토픽 | `WorldState` | **grasp** | planner, web |
| `/control/robot_state` | 토픽 | `RobotState` | control | **web** |
| `/control/safety_events` | 토픽 | `SafetyEvent` | control | web, planner |
| `pick` | 액션 | `Pick` | control | planner(경유 web) |
| `place_into` | 액션 | `PlaceInto` | control | planner(경유 web) |
| `home` | 액션 | `Home` | control | **web** (planner 미경유 — 웹_인터페이스_정의서 2.6절) |

**외부 의존성**: `perception`과 `grasp`는 `realsense-ros` 드라이버가 발행하는 `/camera/depth/image_rect_raw`(`sensor_msgs/Image`)를 구독한다. 이 토픽은 우리가 정의하는 인터페이스가 아니므로 본 문서의 범위에서 제외한다.

### 2.0 world_state 릴레이 구조 (확정)

`WorldState`는 `grasp_candidates`가 채워져야 완성되는데, 그 계산은 `grasp`가 한다. 두 노드가 같은 토픽에 동시에 발행하면 구독자가 "빈 버전"과 "완성 버전" 중 무엇을 받았는지 구분할 수 없는 경쟁 상태가 생기므로, **토픽을 분리해 최종 토픽의 발행자를 하나로 고정**한다.

```
perception ──(world_state_raw, grasp_candidates 없음)──▶ grasp ──(world_state, 완성본)──▶ planner, web
perception ──(instance_masks)──────────────────────────▶ grasp
```

`grasp`는 `world_state_raw`와 `instance_masks`를 같은 `stamp`로 매칭해(`message_filters.ApproximateTimeSynchronizer` 등) 물체별 포인트클라우드를 내부에서 계산하고, `grasp_candidates`를 채운 뒤 `/world_state`로 발행한다. **`planner`/`web`은 `world_state_raw`의 존재를 몰라도 된다** — 완성본(`/world_state`) 하나만 구독하면 그라운딩에 필요한 모든 정보(위치, 속성, 파지 후보)가 이미 들어있다.

`world_state_raw`가 `perception` 네임스페이스에 남아있는 이유는 `perception`이 여전히 그 데이터의 원 출처이기 때문이다. 반면 최종 `/world_state`는 특정 노드 소유가 아닌 **파이프라인의 산출물**이라는 의미로 네임스페이스 접두어를 붙이지 않았다.

## 3. 메시지 정의

### 3.1 GraspCandidate.msg

grasp 노드가 계산한 개별 파지 후보 하나. `DetectedObject`에 중첩되므로 `schema_version` 없음.

```
geometry_msgs/Pose pose        # base 좌표계 기준 파지 자세
float32 score                  # 신뢰도 0.0~1.0

string STRATEGY_HEURISTIC_PCA=heuristic_pca
string STRATEGY_CONTACT_GRASPNET=contact_graspnet
string STRATEGY_GRASPNET_BASELINE=graspnet_baseline
string strategy                # 어떤 방법으로 이 후보를 냈는지 (3단계 비교 실험용)
```

### 3.2 DetectedObject.msg

perception이 발행하는 물체 하나. `WorldState`에 중첩되므로 `schema_version` 없음. `attributes`는 중첩 dict를 지원하지 않는 ROS2 msg 특성상 flatten해서 필드로 둔다.

```
string object_id               # 예: obj_003
string class_name              # 예: tape (objects.yaml의 class_name — 모델 라벨이 아니다, 5.1절)
string name_ko                 # 예: 테이프
float32 confidence

geometry_msgs/Point position_base_mm   # base 좌표계 3D 위치. 단위 mm (1.1절)

float32 depth_valid_ratio      # 낮으면 투명/반사 의심 (8단계 확장에서 활용)
bool graspable
string not_graspable_reason    # graspable=false일 때만 값 있음, 아니면 빈 문자열

# --- 속성 (objects.yaml / object_attributes 테이블과 1:1 대응) ---
float32 mass_g
bool fragile
bool deformable
bool transparent

string PROFILE_NORMAL=normal
string PROFILE_FRAGILE=fragile
string PROFILE_DEFORMABLE=deformable
string profile

string SOURCE_YAML=yaml_seed
string SOURCE_LLM=llm_suggested
string SOURCE_USER=user_confirmed
string attr_source

bool needs_confirmation        # true면 신규 클래스, 사람 확인 대기 (5단계)

GraspCandidate[] grasp_candidates   # grasp 노드가 채워넣음. planner는 이미 채워진 것만 받음
```

**2D 바운딩박스 필드는 없다.** 세그멘테이션으로 검출 방식을 확정했으므로, 픽셀 좌표가 필요한 순간(3D 위치 계산)은 마스크(`InstanceMasks`)로 처리하고 `DetectedObject`에는 이미 계산된 결과만 남긴다.

### 3.3 InstanceMasks.msg

`perception`이 발행하고 `grasp`만 구독하는 내부용 토픽. `WorldState`와 `stamp`로 동기화해서 매칭한다. `grasp`는 이 마스크로 포인트클라우드를 자기 프로세스 안에서만 재구성하며, 그 결과를 다시 밖으로 내보내지 않는다(2.1절).

```
string schema_version
string trace_id
builtin_interfaces/Time stamp
string[] object_ids            # WorldState.objects의 object_id와 1:1 대응
sensor_msgs/Image[] masks      # object_id별 단일 채널 마스크 (mono8, 0/255)
```

### 3.4 WorldState.msg

동일한 스키마가 두 토픽에서 쓰인다 — `perception`이 `/perception/world_state_raw`로 1차 발행할 때는 `objects[].grasp_candidates`가 빈 배열이고, `grasp`가 `/world_state`로 최종 발행할 때는 채워져 있다(2.0절). `planner`/`web`은 `/world_state`만 구독하므로 항상 채워진 버전만 본다.

```
string schema_version
string trace_id
builtin_interfaces/Time stamp
string frame_id                # 보통 "base"

DetectedObject[] objects
string[] needs_reobserve       # graspable=false인 object_id 목록 (능동 재촬영 대상)
```

### 3.5 RobotState.msg

`control`이 주기적으로 발행하는 로봇 상태. 특정 명령·trace에 묶이지 않는 지속 상태라 `trace_id`는 없다.

```
string schema_version
builtin_interfaces/Time stamp

string MODE_IDLE=idle
string MODE_BUSY=busy
string MODE_ERROR=error
string MODE_ESTOPPED=estopped
string mode

string current_skill              # pick/place_into/none — 대시보드 표시용 개략 정보
float32 gripper_width_mm
bool gripper_closed
sensor_msgs/JointState joint_state
```

**구독자는 `web`이다 (`planner`가 아니다).** `planner`가 실시간 ROS2 스트림을 직접 구독하면 NFR-04(LLM 계획 단계는 실시간 제어 루프와 분리)가 흐려진다. `planner`가 로봇 상태를 알아야 하는 판단이 필요하면, `web`이 상태를 보고 HTTP로 `planner`에 전달한다.

### 3.6 SafetyEvent.msg

`control`이 비상정지·충돌·제한 위반 발생 시 발행한다. 특정 요청 중에 발생할 수도, 유휴 상태에서 발생할 수도 있어 `trace_id`/`aborted_request_id`는 선택값이다.

```
string schema_version
builtin_interfaces/Time stamp

string TYPE_ESTOP=e_stop
string TYPE_COLLISION=collision
string TYPE_LIMIT_VIOLATION=limit_violation
string event_type

string SEVERITY_WARNING=warning
string SEVERITY_CRITICAL=critical
string severity

string description
bool requires_manual_reset
string trace_id                 # 진행 중이던 trace가 있었다면 그 ID, 없으면 빈 문자열
string aborted_request_id       # 진행 중이던 Pick/PlaceInto 요청이 있었다면 그 request_id, 없으면 빈 문자열
```

**검증기(FR-12)의 게이트 조건으로 쓴다.** 활성 안전 이벤트가 있으면 `planner`가 새 시퀀스를 생성해도 검증기가 통과시키지 않는다.

## 4. 액션 정의

### 4.1 Pick.action

```
# --- Goal ---
string schema_version
string trace_id
string request_id
string object_id
string profile                 # DetectedObject.profile 값을 그대로 전달 (제어 파라미터 결정)
geometry_msgs/Pose grasp_pose   # planner가 grasp_candidates 중 고른 것
int32 max_retries
---
# --- Result ---
bool success                    # torque 판정 AND visual_verification_passed 모두 통과해야 true

string REASON_NONE=none
string REASON_NO_CONTACT=no_contact
string REASON_GRASP_FAILED=grasp_failed
string REASON_UNREACHABLE=unreachable
string REASON_COLLISION_EXPECTED=collision_expected
string failure_reason

int32 retries_used
float32 cycle_time_ms
float32[] torque_trace_summary  # 접촉~파지 구간 토크 변화 요약값 (원시값은 DB execution_logs로)

bool visual_verification_passed   # 손목 카메라로 그리퍼 사이 물체 유무 확인 (토크만으로 못 잡는 헛파지 보완)
string visual_verification_note   # 실패 시 사유, 예: "그리퍼 사이 빈 공간 감지". 통과 시 빈 문자열
---
# --- Feedback ---
string PHASE_APPROACHING=approaching
string PHASE_CONTACT_DETECTED=contact_detected
string PHASE_LIFTING=lifting
string PHASE_VERIFYING=verifying
string phase
```

**파지 성공 여부는 이 Result가 유일한 근거다.** 별도 상태 토픽으로 중계하지 않는다(2.1절). **성공 판정은 토크 신호 하나에만 의존하지 않는다** — 그리퍼 자체 무게 때문에 "집었다"고 착각하는 헛파지를 토크만으로는 못 거르므로, 손목 카메라로 그리퍼 사이를 확인하는 시각 검증을 더해 두 신호가 모두 통과해야 `success=true`가 된다. 시각 검증은 `perception`(전체 세그멘테이션 파이프라인)을 다시 부르지 않고 `control`이 프레임 하나를 가볍게 확인하는 수준으로 구현한다 — 빠르게 끝나야 하기 때문이다.

### 4.2 PlaceInto.action

```
# --- Goal ---
string schema_version
string trace_id
string request_id
string object_id
string profile
string bin_id                    # bins.yaml에 등록된 목적지 중 하나. LLM은 이 중에서만 선택 가능 (그라운딩)
bool use_pose_override
geometry_msgs/Pose pose_override  # use_pose_override=false면 무시. 1차 범위에서는 사용하지 않으며,
                                   # 확장 단계(정렬 배치 등)에서 bin_pose 기준 정밀 자세 조정이 필요할 때 사용
int32 max_retries
---
# --- Result ---
bool success

string REASON_NONE=none
string REASON_NO_CONTACT=no_contact
string REASON_PLACE_FAILED=place_failed
string REASON_UNREACHABLE=unreachable
string REASON_COLLISION_EXPECTED=collision_expected
string failure_reason

int32 retries_used
float32 cycle_time_ms
---
# --- Feedback ---
string PHASE_MOVING=moving
string PHASE_INSERTING=inserting
string PHASE_RELEASING=releasing
string PHASE_VERIFYING=verifying
string phase
```

**`target_pose`(자유 `Pose`) 대신 `bin_id`를 쓰는 이유**: 1차 범위(분류)의 실제 목적지는 임의의 3D 좌표가 아니라 몇 개의 고정된 박스/트레이다. 자유 좌표를 허용하면 LLM이 목표 위치를 직접 계산해서 내놓아야 하는데, 이는 물체 그라운딩(FR-11) 원칙이 목적지에는 적용되지 않는 셈이 된다. `bin_id`로 제한하면 LLM은 등록된 목적지 중에서만 고르고, 좌표 변환은 `control`이 `bins.yaml`을 참조해 수행한다.

### 4.3 Home.action

```
# --- Goal ---
string schema_version
string request_id
---
# --- Result ---
bool success

string REASON_NONE=none
string REASON_UNREACHABLE=unreachable
string REASON_COLLISION_EXPECTED=collision_expected
string failure_reason

float32 cycle_time_ms
---
# --- Feedback ---
string PHASE_MOVING=moving
string phase
```

**호출자가 planner가 아니라 web이다.** 홈 복귀는 자연어 해석도 그라운딩도 필요 없는 결정적 동작이라 LLM 계획 경로를 지나지 않는다(웹_인터페이스_정의서 2.6절).

**서비스가 아니라 액션인 이유**: 2.6절은 정지를 "`mode`와 무관하게 항상 허용되는 유일한 엔드포인트"로 규정하고, 정지는 진행 중인 액션 goal을 취소하는 방식으로 구현된다. 홈이동을 서비스로 두면 **한번 시작하면 멈출 수 없는 수 초짜리 모션**이 생긴다. 인터페이스 모양을 정한 것은 관례가 아니라 이 요구다.

`trace_id`가 없는 것은 홈이동이 요청 추적 계층(1절)에 편입되지 않기 때문이고, `request_id`가 있는 것은 중복 실행 방지가 추적 계층과 무관한 전송 계층의 계약이기 때문이다. 발급자는 `web/ros_bridge.py`다 — 상위에 발급해 줄 계층이 없다.

`Pick`/`PlaceInto`와 달리 `retries_used`가 없다. 홈 자세는 재시도해서 나아질 종류의 동작이 아니다(실패하면 원인이 경로·충돌이지 파지 불확실성이 아니다).

## 5. 설정 파일 스키마

### 5.1 objects.yaml

물체 속성 마스터의 초기값(seed). 런타임에는 DB `object_attributes` 테이블로 옮겨져 갱신된다. `perception/config/objects.yaml`에 위치.

```yaml
profiles:
  normal:      { max_grip_force_n: 20.0, approach_speed: 0.25, contact_threshold_n: 8.0 }
  fragile:     { max_grip_force_n: 5.0,  approach_speed: 0.08, contact_threshold_n: 3.0 }
  deformable:  { max_grip_force_n: 12.0, approach_speed: 0.20, contact_threshold_n: 5.0 }

model_labels:        # 검출 모델의 클래스명 → 아래 class_name (D-7)
  suncream: suncream
  tape: tape
  nail_product: nail

objects:
  tape:
    name_ko: 테이프
    mass_g: 80
    fragile: false
    deformable: false
    transparent: true
    profile: normal

fallback:            # DB에 없는 신규 클래스에 적용하는 보수적 기본값 (FR-05)
  mass_g: null
  fragile: true
  deformable: false
  transparent: false
  profile: fragile
```

**`model_labels`가 별도 블록인 이유**: 검출 모델의 라벨과 시스템의 `class_name`이 항상 같지는 않다(현재 `nail_product` → `nail`). `perception`이 모델 출력을 `DetectedObject.class_name`으로 옮길 때 이 표를 지나야 한다 — 지나지 않으면 속성 조회가 어긋나 해당 물체가 매번 미확인 신규품목이 되고 FR-05b에 따라 `fragile` 프로파일이 강제된다. **오류로 드러나지 않고 조용히 느려지기만 하는 종류의 어긋남**이라 표를 눈에 보이는 곳에 둔다. 이름이 같은 클래스도 함께 적어 모델 어휘 전체가 한눈에 보이게 한다.

**클래스를 은퇴시켜도 `object_attributes` 행은 남는다.** `execution_logs.class_name`이 이 테이블을 참조하므로(FK), 지우면 과거 이력이 해석 불가능해진다. 시드는 **추가만 한다** — `objects.yaml`에서 클래스를 빼는 것은 "앞으로 이 이름으로 검출되지 않는다"는 뜻이지 "그런 것이 존재한 적 없다"는 뜻이 아니다.

### 5.2 bins.yaml

분류 목적지 정의. 캘리브레이션 단계에서 실측해 고정한다. `control/config/bins.yaml`에 위치.

```yaml
bins:
  left_box:
    name_ko: 왼쪽 박스
    pose: { x: 0.35, y: 0.25, z: 0.05, qx: 0, qy: 0, qz: 0, qw: 1 }
  right_box:
    name_ko: 오른쪽 박스
    pose: { x: 0.35, y: -0.25, z: 0.05, qx: 0, qy: 0, qz: 0, qw: 1 }
```

## 6. 설계 원칙 요약

| 원칙 | 반영 위치 |
| --- | --- |
| 최상위 메시지·API 경계에만 스키마 버전을 붙이고, 중첩 메시지는 부모를 따름 | 1절, `WorldState`/`InstanceMasks`/액션 goal에 `schema_version` |
| 요청 추적은 trace/sequence/request 3단 계층 | 1절, 전 메시지에 전파 |
| 파지 후보는 LLM 판단 이전에 이미 계산되어 있어야 함 | `grasp_candidates`가 `WorldState` 안에 사전 포함 |
| 물체뿐 아니라 목적지도 그라운딩 대상 | `bin_id`로 제한, 자유 좌표 미허용 (1차 범위) |
| 취급 속성이 물리 제어 파라미터를 결정 | `profile`을 액션 goal에 명시적으로 전달 |
| 무거운 데이터(포인트클라우드)는 컨테이너 경계를 넘지 않음 | `grasp` 내부 비공개, 어떤 토픽·서비스로도 노출 안 함 (2.1절) |
| 파지·배치 성공 여부는 액션 Result가 유일한 근거, 별도 상태 토픽 없음 | `Pick`/`PlaceInto` Result |
| 실시간 로봇 상태는 `planner`가 아닌 `web`이 구독 (NFR-04 유지) | `RobotState` 구독자 = web |
| 안전 이벤트는 검증기의 게이트 조건 | `SafetyEvent` → FR-12 검증기 |
| VLM 신뢰 경계 (NFR-03a) | `attr_source='llm_suggested'`이고 `needs_confirmation=true`인 동안은 `profile`이 `fallback` 값으로 고정 |
| 파지 성공 판정은 토크 단일 신호에 의존하지 않음 | `Pick.Result`에 `visual_verification_passed` 추가, torque AND vision 통과 시에만 `success=true` |
| 검증기를 통과한 시퀀스는 사람의 매 실행 승인 없이 자동 실행됨(신규 물체 확인 절차 FR-05b는 별개, 계속 유지) | `task_sequences`에 실행 전 승인 단계 없음. 안전은 검증기(그라운딩·작업공간·가반하중·SafetyEvent 게이트)와 하드웨어 비상정지가 담당 |

## 7. 미확정 항목

- `grasp`가 `world_state_raw`+`instance_masks` 동기화에 쓸 정확한 매칭 정책 (`ApproximateTimeSynchronizer`의 허용 시간차 등) — 실측 후 튜닝
- 검증기(FR-12)의 "목적지 그라운딩" 체크 로직 — `bin_id`가 `bins.yaml`에 없을 때 거부 응답의 정확한 스키마

- `RobotState`를 DB에 얼마나 자주 스냅샷할지 (매 프레임 기록은 과함, 주기 미정)
