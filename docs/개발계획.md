## 2. 개발 순서 재조정 (핵심 결정)

BR 로드맵의 숫자 순서(1단계 검출 → 2 세그멘테이션 → 3 파지 → 4 LLM)를 그대로 따르지 않고, **web·planner 계층을 먼저 개발**한다.

**근거**

1. 검출 모델 선정·학습은 현재 **Colab에서 병렬 진행 중**이다. 워크스테이션 트랙이 그 결과를 기다리며 놀 이유가 없다.
2. `WorldState`·HTTP API·화면 구성이 **이미 문서로 확정**되어 있다. 즉 perception의 실제 출력이 없어도, 같은 스키마의 mock 데이터로 상위 계층 전체를 개발·검증할 수 있다.
3. BR 7절 제약("실물 로봇 실험 시간이 제한적이므로 로봇 없이 검증 가능한 작업을 최대화한다")과 정확히 같은 방향이다.
4. web·planner는 GPU를 쓰지 않는다. Colab 학습과 워크스테이션 개발이 자원 경합 없이 동시에 돌아간다.

**단계 번호와의 매핑**: 여기서 먼저 만드는 것은 실질적으로 **4단계(LLM 지시 기반 분류)의 계획·검증·웹 부분**이다. 1~3단계(검출·세그멘테이션·파지)가 완성되면 mock 어댑터를 실제 `/world_state` 구독으로 교체하는 것으로 결합한다. 이 교체가 한 지점에서만 일어나도록 만드는 것이 트랙 B의 설계 목표다(4.2절 B2).

### 2.1 트랙 구성

| 트랙 | 장소 | 내용 | 의존성 |
|---|---|---|---|
| A | Colab | 검출 모델 선정·학습 (1~2단계) | 없음 (진행 중) |

## 4. 트랙 B: planner + web (우선 개발)

### 4.1 원칙

- **mock은 별도 코드 경로가 아니라 어댑터 교체다.** `web`이 `ros_bridge`를 부르는 인터페이스를 먼저 고정하고, 실제 구현과 mock 구현이 같은 시그니처를 갖게 한다. STT를 별도 실행 경로로 만들지 않는 FR-23과 같은 원칙이다.
- **검증기는 LLM 프롬프트를 신뢰하지 않는다.** 그라운딩(FR-11)은 프롬프트로 유도하되, 최종 판정은 코드(`validator.py`)가 한다.
- 각 단계는 그 자체로 검증 가능한 산출물을 남긴다(BR 8절 리스크 대응 — 어느 지점에서 멈춰도 제출 가능).

## 5. 트랙 A·C

### 5.1 트랙 A (Colab) — 트랙 B와의 합류 조건

Colab 실험이 끝났다고 판단하려면 아래가 정해져야 한다. 모델 성능 수치보다 **인터페이스 확정**이 합류의 조건이다.

| 확정 항목 | 왜 필요한가 |
|---|---|
| 최종 클래스 목록 | `objects.yaml` 시드(D-7), 평가셋 물체명 |
| 모델 출력 → `DetectedObject` 매핑 | `class_name`·`confidence`·마스크가 어떤 형태로 나오는지 |
| 마스크 형식 | `InstanceMasks.masks`는 mono8 0/255 단일 채널 |
| 추론 시간/VRAM | perception·grasp 순차 추론 설계(시스템명세서 4.2절)가 실제로 성립하는지 |
| 자동 라벨링 품질 | 자동 라벨 vs 수동 라벨 IoU — 이 수치 없이는 라벨 품질을 주장할 수 없다 |

산출물: `docs/results/detection_report.md` (BR 1단계 mAP 리포트).

### 5.2 트랙 C — 0단계 잔여

## 6. 마일스톤

| # | 내용 | 트랙 | 검증 방법 |
|---|---|---|---|
| M0 | 0단계 산출물 완결 | C | `calibration_report.md` 존재, `bins.yaml` 실측값 |
| M1 | planner 단독 동작 | B (B0·B1) | mock 픽스처 5종에 대해 `/internal/plan`이 승인/거부를 올바르게 반환 |
| M2 | web 백엔드 + mock 실행 | B (B2) | 로봇·GPU 없이 명령→계획→실행→WebSocket 진행률 도달 |
| M3 | 화면 2종 완성 | B (B3) | 브라우저에서 mock 시나리오 시연 가능 |
| M4 | ROS2 경로 E2E (fake robot) | B (B4) | `FAKE_ROBOT=1`로 M3와 동일 시연 |
| M5 | perception/grasp 실물 결합 | A+B | `executor.py` 구현만 교체하고 `main.py`·프론트 무수정으로 동작 |
| M6 | 4단계 지표 리포트 | B (B5) | 명령 정확도·거부 정확도 수치 산출 (**1차 목표 달성 지점**) |

M1~M4는 로봇 접근 시간과 무관하게 진행 가능하다. M5는 트랙 A 완료가 선행 조건이다.

## 7. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| mock과 실제 `world_state`의 괴리 | M5에서 상위 계층 재작업 | 픽스처를 `WorldState.msg` 스키마에서 직접 생성하고, 필드 추가 시 픽스처를 함께 갱신 |
| mm 규칙과 ROS 관례(m)의 충돌 | MoveIt2·tf2에 mm 값이 그대로 들어가면 1000배 좌표 오차 → 충돌 위험 | 환산을 `control/control/units.py` 한 곳으로 제한(D-1 예외 조항), 필드명 단위 접미사로 오용을 눈에 띄게 함. `control` 구현 시 이 경계에 테스트를 먼저 둔다 |
| 어댑터 경계가 새어 `main.py`가 ROS2를 알게 됨 | 컨테이너 분리 원칙(NFR-06) 붕괴, mock 개발 이점 상실 | `main.py`에 `rclpy` import 금지를 리뷰 기준으로 고정 |
| LLM API 비용 (평가셋 반복 실행) | 예산 초과 | 고정 프리픽스를 앞에 두어 프리픽스 캐싱을 살리고, 평가셋 전체 실행은 프롬프트 버전이 바뀔 때만. `eval_runs`에 버전별로 기록해 같은 조건 재실행을 피한다 |
| 트랙 A 지연 | M5·M6 지연 | M1~M4가 독립적으로 완결되므로 어느 시점에 멈춰도 시연 가능한 상태 유지 |
| 캘리브레이션 오차가 큼 | 자동 라벨링 투영(트랙 A 3.3절)이 통째로 틀어짐 | M0의 TCP 실측 오차를 트랙 A 데이터 수집 착수 전에 확인 |
