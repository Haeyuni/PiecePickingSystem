# BR: 자연어 지시 기반 협동로봇 다품종 분류·피스피킹 시스템

| 항목 | 내용 |
| --- | --- |
| 문서 버전 | v1.0 |
| 작성 목적 | 부트캠프 졸업 프로젝트 / 포트폴리오 시스템 개발 요구사항 정의 |
| 대상 완료 시점 | 2026년 10월 (두산로보틱스 소프트웨어 아카데미 수료) |

---

## 1. 개요

### 1.1 배경

다품종 소량 생산·물류 현장에서 협동로봇 도입이 지연되는 핵심 원인은 파지 알고리즘의 정확도가 아니라 **품목이 바뀔 때마다 발생하는 재티칭 비용**이다. 씨메스로보틱스, 두산로보틱스 등 국내 로봇 기업의 채용공고와 제품 사양은 공통적으로 "비정형 물체 대응", "등록되지 않은 제품의 무프로그래밍 처리", "자연어 명령 기반 태스크 플래닝"을 핵심 과제로 제시하고 있다.

### 1.2 목적

자연어 명령으로 다품종 물체를 인식·분류·배치하는 협동로봇 시스템을 구축하여, 신규 품목 투입부터 작업 개시까지의 시간을 단축하는 것을 목표로 한다. 1차 목표는 **분류(sorting)** 태스크이며, 이후 **피스피킹(piece picking)** 수준의 산업 시나리오로 확장 가능한 구조로 설계한다.

### 1.3 핵심 가설

> LLM 기반 태스크 플래닝과 검증 계층을 인지·제어 파이프라인에 결합하면, 재프로그래밍 없이 신규 품목과 신규 작업 지시에 대응하는 협동로봇 시스템을 만들 수 있다.
>

## 2. 범위

### 2.1 In Scope (1차 개발 범위)

- 트레이/바구니에 무작위로 놓인 다품종 물체의 인식·분류·배치
- Web UI 자연어(텍스트) 명령 기반 작업 지시
- 순응제어 기반 파지·배치 (접촉 감지, 파지 성공 판정, 무게중심 오차 재파지)
- 실행 전 시퀀스 검증

### 2.2 2차 개발 범위

- 신규 품목에 대한 확인 후 속성 등록 루프
    - 사용자 승인 절차
- Web UI + **음성 인터페이스(STT)**

### 2.3 확장 개발 범위

- 투명 물체 파지
- 기울어진 물체
- 하차/탐색(바구니 속 특정 물체 탐색) + 싱귤레이션
- 움직이는 물체(컨베이어 동적 픽업)

### 2.3 확장성 설계 원칙

1차 분류 시스템은 향후 피스피킹 수준(무작위 적재 대응, 클러터 처리, 컨베이어 연동)으로 확장 가능하도록 다음을 인터페이스 계약으로 고정한다.

- 인지 계층 출력(월드 상태 JSON)은 검출 방식(bbox → segmentation)이 바뀌어도 하위 계층이 영향받지 않는 구조
- 파지 계층은 전략 패턴(휴리스틱 ↔ 학습 기반 모델)으로 교체 가능하게 설계
- 스킬 실행기는 신규 스킬(예: `push`, `search`, `singulate`) 추가가 기존 스킬 수정 없이 가능한 구조
- LLM 플래너-검증기 인터페이스는 신규 명령 유형(탐색, 다단계 작업) 확장을 전제로 설계

## 4. 기능 요구사항 (단계별)

### 4.1 개발 단계 개요

| 단계 | 목표 | 산출물 |
| --- | --- | --- |
| 0단계 | 하드웨어 배선, hand-eye calibration | 캘리브레이션 검증 리포트(재투영 오차, TCP 실측 오차) |
| 1단계 | 학습 데이터 기반 물체 인식 확인 | 검출 모델 mAP 리포트 |
| 2단계 | 인식 segmentation 및 물체 간격 실험 | 클러터 밀도별 성능 비교표 |
| 3단계 | 픽업 방법 비교 (중심점 vs GraspNet), 무게중심 재파지 로직 | 파지 성공률 ablation 리포트 |
| 4단계 | LLM 지시 기반 분류 동작 확인 | 평가셋 기반 명령 정확도·거부율 리포트 |
| 5단계 | 신규 품목에 대한 확인 후 속성 등록 루프

    ◦ 사용자 승인 절차 |  |
| 6단계 | 웹 UI 음성 명령 확장 (마이크 콜아웃 → STT → 기존 텍스트 파이프라인 재사용) |  |
| 7단계 | 기울어진 물체 |  |
| 8단계 | 투명 물체 파지 |  |
| 9단계 | 하차/탐색(바구니 속 특정 물체 탐색) + 싱귤레이션 |  |
| 10단계 |  움직이는 물체(컨베이어 동적 픽업) |  |

### 4.2 인지 계층

- **FR-01** 시스템은 RGB-D 손목 카메라로 트레이/바구니 내 물체를 검출해야 한다.
- **FR-02** 검출 결과는 클래스, 신뢰도, 세그멘테이션 마스크, 3D 위치를 포함해야 한다.
- **FR-03** 뎁스 유효 비율이 임계값 미만인 경우(투명·반사 물체 등) `graspable=false`로 표시하고 능동 재촬영 대상으로 지정해야 한다.
- **FR-04** 검출된 물체는 속성 DB(무게, 파손 위험, 변형 여부, 순응제어 프로파일)와 결합되어야 한다.
- **FR-05** 속성 DB에 없는 신규 클래스는 `needs_confirmation=true`로 표시하고, 사람이 확정하기 전까지는 보수적 기본값(fragile 프로파일)으로만 시도해야 한다.
- **FR-05a (VLM 기반 속성 제안)** 신규 클래스 발견 시, 시스템은 마스크로 크롭된 이미지를 VLM(비전 지원 LLM)에 전달하여 이름·재질·파손위험 여부를 1차로 제안받아야 한다. 제안된 속성은 `source=llm_suggested`, `is_confirmed=false` 상태로 속성 DB에 선기록되어야 한다.
- **FR-05b** VLM이 제안한 속성은 사람의 확인(원클릭 승인 또는 수정) 없이는 확정(`is_confirmed=true`)되지 않아야 한다. 확인 전까지 해당 클래스에 대한 모든 파지 시도는 FR-05의 보수적 기본값을 따라야 하며, VLM이 제안한 속성값(무게·파손위험 등)이 파지력·접근속도 같은 물리적 제어 파라미터에 직접 반영되어서는 안 된다.
- **FR-05c** 동일 세션 내에서 이미 제안·확인된 클래스에 대해서는 VLM을 재호출하지 않고 캐시된 값을 사용해야 한다.
- **FR-06 (확장)** 클러터 상황에서 RGB 세그멘테이션과 뎁스 불연속을 결합하여 맞닿은 물체를 분리해야 한다.

### 4.3 파지 계층

- **FR-07** 시스템은 물체별 6-DoF 파지 후보를 생성해야 하며, 최소 두 가지 전략(기하학적 중심 기반, 학습 기반 모델)을 지원해야 한다.
- **FR-08** 파지 실행 후 관절 토크 변화를 기반으로 무게중심 오차를 검증하고, 임계값 초과 시 재파지를 시도해야 한다.
- **FR-09** 재시도 횟수는 설정 가능해야 하며, 최대 횟수 초과 시 실패로 기록하고 다음 물체로 진행해야 한다.

### 4.4 계획·검증 계층

- **FR-10** 시스템은 자연어 명령과 현재 인지된 물체 목록(월드 상태)을 입력으로 받아 스킬 시퀀스를 생성해야 한다.
- **FR-11** LLM은 실제 검출된 object_id로만 그라운딩되어야 하며, 검출되지 않은 물체에 대한 지시는 시퀀스 대신 거부 응답을 반환해야 한다.
- **FR-12** 생성된 시퀀스는 실행 전 검증기를 통과해야 하며, 검증 항목은 스키마 유효성, 작업공간 경계, 가반하중, 스킬 전제조건을 포함해야 한다.
- **FR-13** 물체의 취급 속성(파손 위험 등)은 스킬 파라미터(그리퍼 파지력, 접근 속도)에 반영되어야 한다.

### 4.5 실행 계층

- **FR-14** 스킬 실행기는 `pick`, `place_into`를 최소 스킬셋으로 제공해야 한다.
- **FR-15** 각 스킬은 접촉 감지, 파지/배치 성공 판정, 실패 사유 분류(접촉 없음/파지 실패/도달 불가/충돌 예상)를 포함해야 한다.
- **FR-16** 스킬 실행 실패 시 구조화된 실패 사유가 플래너로 반환되어 재계획을 트리거해야 한다.
- **FR-17 (확장 인터페이스)** 신규 스킬(`push`, `search` 등)은 기존 스킬 구조를 변경하지 않고 추가 가능해야 한다.

### 4.6 웹/운영 계층

- **FR-19** 웹 UI는 명령 입력, 계획된 시퀀스 미리보기, 실행 승인, 실행 로그 조회 기능을 제공해야 한다.
- **FR-20** 모든 실행 시도는 성공/실패 여부, 실패 사유, 측정된 센서값과 함께 로깅되어야 한다.

### 4.7 음성 인터페이스

물류센터·제조 현장 작업자가 양손이 차 있거나 장갑을 착용한 상태에서도 명령을 내릴 수 있어야 한다는 현장 요구사항에 근거해, 텍스트 명령 파이프라인이 4단계에서 안정화된 이후 음성 입력을 추가한다.

- **FR-22** 웹 UI는 마이크 버튼(콜아웃)을 제공해야 하며, 사용자가 버튼을 눌러 음성 녹음을 시작·종료할 수 있어야 한다.
- **FR-23** 녹음된 음성은 STT로 텍스트 변환되어 **기존 FR-10(명령 입력) 이하 파이프라인을 그대로 재사용**해야 한다. 즉 음성 전용 처리 경로를 별도로 만들지 않고, 텍스트 변환 결과가 기존 명령 입력과 동일한 인터페이스로 들어가야 한다.
- **FR-24** STT 변환 결과(인식된 텍스트)는 실행 전 화면에 표시되어 사용자가 확인·수정할 수 있어야 한다. 오인식 상태로 곧바로 계획·실행 단계로 넘어가서는 안 된다.
- **FR-25** STT 신뢰도가 낮거나 무음/잡음으로 판단되는 경우, 명령을 생성하지 않고 재입력을 요청해야 한다.

**설계 제약**: FR-13(실행 전 사용자 승인)은 음성 명령에도 동일하게 적용된다. 오인식된 음성이 승인 절차 없이 로봇을 움직이는 경로는 존재해서는 안 된다(NFR-03과 동일한 원칙).

## 5. 비기능 요구사항

### 5.1 안전

- **NFR-01** 비상정지는 소프트웨어 계층과 독립적으로 로봇 제어박스에 하드웨어로 직결되어야 한다.
- **NFR-02** 작업공간 경계, 가반하중 한계는 검증기에서 실행 전 반드시 체크되어야 한다.
- **NFR-03** LLM 출력은 어떤 경우에도 코드 생성이 아닌 사전 정의된 스킬 시퀀스로 제한되어야 한다.
- **NFR-03a (VLM 신뢰 경계)** VLM은 이름·재질 등 인지적 판단에만 사용하며, 무게·파손위험 같은 물리적 속성 추정치를 사람 확인 없이 제어 파라미터(파지력·속도)에 직접 반영해서는 안 된다. 사진 기반 추정과 실제 물성은 다를 수 있다는 것을 설계 전제로 한다.

### 5.2 성능

- **NFR-04** LLM 계획 단계는 실시간 제어 루프(순응제어)와 분리되어야 하며, 제어 루프에 LLM 응답 지연이 영향을 주어서는 안 된다.
- **NFR-05** 시스템은 명령 입력부터 실행 시작까지의 지연시간을 측정·기록해야 한다.
- **NFR-05a (음성 확장)** STT 처리는 LLM 계획 단계와 동일하게 실시간 제어 루프와 분리되어야 하며, 텍스트 명령 대비 추가되는 지연시간(녹음+변환)을 별도로 측정·기록해야 한다.

### 5.3 확장성

- **NFR-06** 인지 계층, 파지 계층, 계획 계층, 실행 계층은 독립적으로 교체 가능한 서비스 단위로 분리되어야 한다(컨테이너화).
- **NFR-07** 물체 속성 DB는 신규 물체 추가 시 코드 변경 없이 데이터 추가만으로 반영되어야 한다.
- **NFR-08** 스킬 스키마는 신규 파라미터(목표 자세의 6D 확장 등) 추가에 열려 있어야 한다.

### 5.4 재현성

- **NFR-09** 모든 실험은 설정값(모델 버전, 프롬프트 버전, 임계값)을 기록하여 재현 가능해야 한다.
- **NFR-10** 신규 품목 평가용 물체군은 학습 데이터 수집 단계부터 물리적으로 격리되어야 한다.

### 6.2 소프트웨어 서비스 구성 (컨테이너 단위)

| 서비스 | 역할 |
| --- | --- |
| perception | 물체 검출/세그멘테이션, 월드 상태 발행 |

## 7. 제약사항 및 가정

- SG2가 소프트/평행 그리퍼 계열이라는 전제하에, 정밀 방향 제어가 필요한 조립 작업은 범위에서 제외한다.
- LLM은 외부 API 호출을 전제로 하며, 네트워크 의존성이 발생한다.
- 실물 로봇 실험 시간이 제한적이므로, 로봇 없이 검증 가능한 작업(오프라인 평가, mock 데이터 기반 개발)을 최대화한다.

## 9. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 그라운딩 | LLM이 실제 인지된 물체 목록에만 근거하여 판단하도록 제한하는 설계 |
| 순응제어 | 힘/토크 센서 피드백을 기반으로 접촉 상황에 반응하는 제어 방식 |
| 싱귤레이션 | 뒤엉킨 물체 더미를 개별 파지가 가능한 상태로 분리하는 동작 |
| 능동 인지 | 첫 관측이 불충분할 때 카메라 위치를 이동해 재관측하는 방식 |
| 피스피킹 | 낱개 단위 상품을 개별적으로 파지·이송하는 물류 작업 |
| STT | Speech-to-Text. 음성을 텍스트로 변환하는 처리. 본 시스템에서는 변환 결과를 기존 텍스트 명령 파이프라인의 입력으로 그대로 사용한다 |
| VLM | Vision-Language Model. 이미지와 텍스트를 함께 이해하는 모델. 본 시스템에서는 신규 물체의 크롭 이미지를 전달해 이름·재질 등을 1차 제안받는 용도로만 사용하며, 물리적 제어 파라미터에는 직접 반영하지 않는다 |
